Getting started

Both platforms follow the same build order. Start with a bench setup on a breadboard, prove each sensor individually, then assemble the full enclosure.

  1. Order the BOM for your platform (see below) and verify each part against the datasheet pinout.
  2. Flash the reference firmware to the microcontroller with the default test configuration.
  3. Connect one sensor at a time; the firmware's self-test prints each channel's readings over serial.
  4. Run the loop with actuators on the bench for 48 hours before any culture or substrate is introduced.
  5. Calibrate (see Calibration), then introduce the culture or spawn and watch the twin learn its baseline.
Golden rule

Never let the AI control a culture before you can control it by hand. The failsafe is a backstop, not a beginner strategy.

Electrical safety

Mains wiring is not a beginner project. If you are not confident working with mains voltage, use a 12 V low-voltage design or have an experienced person review the enclosure before first power-up.

Firmware

The reference firmware is a single-loop state machine. It never blocks on a sensor: every channel has a freshness timestamp, and a reading older than its timeout is treated as "unknown," which the safety gate treats as "no action."

loop():
    now = millis()
    for sensor in sensors: sensor.poll(now)     # non-blocking, timeout-aware
    if wifi.connected and mqtt.dues(now): mqtt.publish_telemetry()
    if twin.due(now): twin.update(state, now)   # forward simulation
    action = controller.propose(state, setpoints)
    if safety_gate.allows(action, state):       # rules -> twin sim -> clamps
        actuators.apply(action)
    else:
        actuators.hold()                        # fail closed
    sleep(100ms)

Digital twin models

Simulations & their limits

The Mycophyte simulation and the AlgaePhyte simulation on the site run the same control logic and the same illustrative model equations shown above. They are educational tools for understanding the control loop â€” not validated experimental results, and not performance claims.

Specifically, the simulations do not model: strain-specific biology, contamination propagation, actuator degradation, sensor noise beyond a cosmetic jitter, or enclosure geometry. If you need defensible numbers, run the hardware and log real telemetry.
