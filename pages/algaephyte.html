System Overview

Four Capabilities, One Living Culture

MAIN runs on a Raspberry Pi Zero 2W. It reads six sensors continuously, runs a physics-based digital twin of the culture, lets an AI pipeline propose the next action, validates every proposal through a two-layer safety gate, and learns from every outcome through ChromaDB memory — all while sharing improved model parameters across a federated network.

01

It Senses

Six analog sensors — pH, temperature (DS18B20), light (BH1750), optical density (TSD-10), dissolved oxygen, and TDS — read through an MCP3008 ADC. Optional ESP32-CAM for microscope-grade vision. Every reading logged to CSV and published over MQTT.

02

It Predicts

A Droop cell-quota model with Steele photoinhibition, Beer-Lambert self-shading, and temperature/pH/DO response curves. The twin forecasts 24-hour growth, simulates proposed actions before execution, and self-calibrates against real data every 6 hours.

03

It Protects

Two-layer safety gate: deterministic hard limits (pH 8.5–10.5, temp 20–35°C, nutrient ≤ 20mL) then a 24-hour twin simulation. If either layer rejects, the action is blocked. Firmware clamps and a physical GPIO15 emergency stop sit underneath as independent backstops.

04

It Learns

ChromaDB with Sentence-Transformer embeddings stores every validated experiment. LangGraph retrieves similar past experiments for AI context. PhycoNet shares tuned twin parameters across reactors — never raw culture data — so the network converges faster than any single reactor alone.

The Digital Twin: Four Equations That Model a Living Culture

The twin is a system of ODEs solved with SciPy's solve_ivp. It tracks four state variables — cell density (X), internal nutrient quota (Q), external nutrient concentration (N), and product concentration (P). Four coupled equations drive the simulation:

1. Droop cell-quota kinetics: Growth rate μ = μmax × (1 − Q₀/Q). When the cell's internal nutrient store runs low, growth slows — not instantaneously, but gracefully.

2. Steele photoinhibition: Light uptake follows a peaked curve. Too little light limits photosynthesis; too much light damages the photosystems. The twin finds the optimum.

3. Beer-Lambert self-shading: As cells multiply, they cast shade on each other. Light intensity drops exponentially through the culture depth. The twin integrates across the reactor to compute the average light each cell actually sees.

4. Temperature, pH, and DO response: Each environmental factor modulates growth through a bell-shaped response curve centered on the species optimum. Spirulina peaks at ~35°C and pH ~9.5; the twin knows both.

# digital_twin.py — the growth rate equation def predict_growth_rate(state, I0, T, pH, DO): mu = mu_max * (1.0 - Q0 / Q) # Droop quota I_avg = I0 * (1 - exp(-k * X * d)) / (k * X * d) # Beer-Lambert mu *= steele_response(I_avg, I_opt) # Steele curve mu *= temperature_response(T, T_opt, T_range) mu *= ph_response(pH, pH_opt, pH_range) mu *= do_inhibition(DO, DO_crit) return mu # Twin self-calibrates every 6 hours def fit_to_data(telemetry_history): # Fits mu_max, I_opt, Q0 to match observed growth params = curve_fit(growth_model, telemetry_history) self.update_parameters(params)

The AI Brain: Gemini + Groq + ChromaDB

The AI layer uses a dual-provider strategy: Gemini for deep scientific reasoning (interpreting algal biology, cross-referencing strain knowledge), and Groq for fast, low-latency structured JSON formatting. The LangGraph-based MAINAgent orchestrates the workflow.

The prompt fed to the AI includes: (1) the current raw sensor snapshot, (2) the twin's 24-hour growth forecast, (3) similar past experiments retrieved from ChromaDB, and (4) the user's cultivation goal. The AI reasons across all four inputs simultaneously.

When the internet drops, a lightweight local fallback takes over: a rule-based heuristic on the Pi itself, or if Ollama is installed, a small local model (qwen2.5:0.5b) can generate proposals offline. The culture is never left without guidance.

Safety Architecture: Two Independent Gates

Layer 1

Hard Limit Validation

Deterministic rule check against configurable bounds. pH must stay 8.5–10.5, temperature 20–35°C, nutrient pulse ≤ 20mL, bicarbonate ≤ 5g, light 100–400 µE/m²/s. Unknown action types are rejected. Every value is bounds-checked and finite-checked. This layer runs in microseconds — no network, no model, no ambiguity.

Layer 2

Digital Twin Simulation

The proposed action is simulated for 24 hours in silico before a single pump moves. The twin computes the resulting pH shift, the predicted growth rate, and nutrient drawdown. If growth drops below threshold, pH drifts into danger, or any value becomes non-finite, the action is blocked. It fails closed. There is no path from AI proposal to actuator that doesn't pass through this gate.

# safety/controller_validator.py — the two-layer gate def validate_with_simulation(proposal, state, env): # Layer 1: hard limits ok, reason = self.validate_hard_limits(proposal) if not ok: return False, reason # Layer 2: simulate the dose ph1 = env["ph"] + 0.06 * (value / volume_l) if ph1 > self.limits.ph_max: return False, f"pH {ph1:.2f} exceeds safe max" growth = self.twin.predict_growth_rate( state, I0=env["light"], T=env["temp"], pH=ph1, DO=env["do"]) if not math.isfinite(growth): return False, "NaN growth; blocking" return (growth >= self.threshold), "approved"

MQTT → GPIO → Actuator, Then Record Outcome

Approved commands are published to gaon/pbr/{id}/command over MQTT. The Pi's mqtt_client.py subscriber receives it, passes it through a final hardware-side validation, and activates the corresponding GPIO pin — triggering the pump, adjusting the LED PWM, or switching the heater relay.

CRITICAL: The outcome is only stored after the action has been executed and its effects measured. MAIN never learns from proposals that were never tested. The record_outcome() method enforces this — it will refuse to store an experiment with no outcome data.

Safety Architecture

The Safety Gate — Why MAIN Fails Closed

Every AI proposal passes through two independent validation layers before a single actuator moves. There is no backdoor — the AI cannot bypass these gates, and both must return "approved" for any action to proceed. Below that sits a physical emergency stop on GPIO15 that cuts all actuators with a single press.

Layer 1

Hard Limits

Deterministic bounds checks in safety/controller_validator.py. Runtime in microseconds. No network, no AI. Every value must be finite and within configurable bounds.

  • pH: 8.5–10.5
  • Temp: 20–35°C
  • Nutrient pulse: ≤ 20mL
  • Bicarbonate: ≤ 5g
  • Light: 100–400 µE/m²/s
  • Clean cycle: ≤ 120s
  • Unknown actions: rejected
Layer 2

Twin Simulation

24-hour forward simulation of the proposed action. If the predicted growth rate drops below threshold, or any state value becomes non-finite, the action is rejected.

  • Simulates pH shift from dose
  • Forecasts 24h growth trajectory
  • Checks nutrient drawdown
  • NaN/Inf guard: blocks on non-finite
  • Fail-closed: reject on uncertainty
Layer 3

Physical E-Stop

GPIO15 on the Pi. Active-low with pull-up. Press the button, and all actuator GPIO pins drop. Independent of software — runs even if the Python interpreter has crashed.

  • Hardware interrupt (GPIO15)
  • Cuts all pumps, lights, heaters
  • Works with dead CPU
  • Latched: requires RESUME command
  • Dashboard STOP_ALL button

Memory System

ChromaDB: How MAIN Learns from Every Experiment

Every validated experiment — the sensor snapshot, the proposal, and the measured outcome — is embedded and stored in ChromaDB. When the AI brain generates its next proposal, it retrieves similar past experiments for grounding context. It doesn't just guess; it remembers what worked.

ChromaDB · Vector Store Sentence-Transformers embeddings

Each experiment is flattened to natural language, embedded with all-MiniLM-L6-v2, and stored in a persistent ChromaDB collection. Retrieval uses cosine similarity on the embedding space — the model finds experiments that are meaningfully similar, not just keyword-matched.

PUMP_NUTRIENT 15mL +0.12 g/L

When ChromaDB is unavailable (e.g. on a Pi Zero 2W), falls back to keyword-scored JSONL retrieval automatically.

# memory.py — store & retrieve def store_experiment(proposal, sensor_context, outcome): text = _experiment_to_text(proposal, sensor_context, outcome) embedding = embedder.encode(text) collection.add( ids=[uuid4()], embeddings=[embedding], documents=[text], metadatas=[{ "action": proposal.action, "value": proposal.value, "actual_result": outcome.biomass_delta_g_l, "validated": True, }]) def retrieve_similar(proposal, n=3): query_embedding = embedder.encode(query_text) results = collection.query( query_embeddings=[query_embedding], n_results=n) return format_for_prompt(results)
Federated Learning

PhycoNet: Reactors That Learn from Each Other

Every 12 hours, each reactor shares its calibrated twin parameters — μmax, Iopt, Q₀, and response curve parameters — via MQTT. An aggregator computes a weighted average by reactor performance. The improved global model is redistributed. No raw culture data ever leaves a reactor. The network converges on a strain's productive regime faster than any single reactor could alone.

OFFLINE MODE

When home Wi-Fi is unavailable, MAIN runs fully offline: telemetry stays local on CSV, the local AI fallback (heuristic rules or Ollama) generates proposals, and the dashboard over the hotspot works perfectly. No internet means no cloud AI — but the culture stays managed. When connectivity returns, buffered telemetry flushes and the cloud brain resumes.

Software Architecture

Every Module, What It Does

The Python modules that make MAIN work — from the sensor driver to the federated network.

main.py

System Controller

Orchestrates the sensor loop. Reads all sensors every 60 seconds, updates the OLED, publishes MQTT telemetry, checks the emergency stop, and manages the main execution thread. The heartbeat of the entire Pi side.

hardware_driver.py

Hardware Abstraction

Wraps all GPIO, ADC, I2C, and OneWire interactions. Provides a clean read_all_sensors() API so the rest of the system never touches raw pins. Handles calibration, noise filtering, and sensor health monitoring.

digital_twin.py

AlgaeTwin

Droop + Steele + Beer-Lambert ODE system. simulate() for 24h forecasts, predict_growth_rate() for instant checks, fit_to_data() for self-calibration. NaN-guarded at every boundary.

ai/agent.py

MAINAgent (LangGraph)

Stateful AI workflow: builds the prompt, invokes the router (Gemini for reasoning, Groq for structured output), passes results to the decision synthesizer, and records outcomes back to ChromaDB. Guaranteed fallback to NO_ACTION on any failure.

ai/router.py

AIController

Complexity-based provider routing. Gemini handles deep biological reasoning and multi-step optimization. Groq handles fast structured JSON and routine decisions. Both feed into a DecisionSynthesizer that produces the final ValidatedCommand.

safety.py

SafetyValidator

Configurable SafetyLimits dataclass + two-layer validation. validate_hard_limits() checks bounds, validate_with_simulation() runs the twin. Unknown actions rejected. Non-finite values blocked. Always fails closed.

memory.py

ChromaMemory

ChromaDB-backed with Sentence-Transformer embeddings. Stores every validated experiment. retrieve_similar() uses cosine similarity. Falls back to keyword-scored JSONL on constrained hardware. Deduplicates entries.

federated.py

PhycoNet

Shares calibrated twin parameters via MQTT every 12 hours. Receives global model updates. Applies weighted averaging. Validates all incoming parameters for finiteness and bounds before touching the live twin. Never shares raw data.

mqtt_client.py

MQTT Communication

Handles all broker communication. Paho MQTT client with automatic reconnect, offline buffering, TLS support, and username/password auth. Subscribes to command topics; publishes telemetry, acks, and heartbeats.
